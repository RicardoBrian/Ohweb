# SeatChange

교실 모양 그대로 책상을 배치하고, 명렬표를 올리면 규칙에 맞게 자리를 바꾼다.
배치가 끝나면 책상은 비워져 있고, 학생이 자기 책상을 눌러야 이름이 화면에
크게 나온다.

`kakainfo.com` 계열 앱들과 같은 규격이다 — 빌드 스텝 없음, `public/`이 그대로 배포,
`theme.css`는 `design-reference/`와 동일한 사본.

## 구조

```
public/
  index.html           화면
  app.js               상태 관리 · 렌더링 · 책상 편집 · 드래그
  app.css              페이지 전용 스타일 (theme.css 토큰만 사용)
  arrange.js           배정 엔진 — DOM 의존 없음
  store.js             Firestore 저장 계층 — 방 열기/저장/공유 링크
  firebase-config.js   Firebase 초기화 + 익명 인증
  theme.css            공용 디자인 시스템 (design-reference에서 복사)
arrange.test.mjs       엔진 테스트
firestore.rules        Firestore 보안 규칙
rules-test/            firestore.rules 에뮬레이터 테스트
```

## 화면 구조

메인 화면은 곧 교실 보드다. 제목 바로 아래 칠판과 책상 격자가 항상 보이고,
숫자 카드나 별도 설정 화면이 앞을 가리지 않는다. 명단·규칙·짝 금지 같은
설정은 톱니바퀴 아이콘을 눌러야 나오는 슬라이드 패널에 몰아뒀다 — 프로젝터에
띄웠을 때 설정 UI가 보이면 안 되기 때문이다.

**설계 모드**(아직 배치 전)와 **배치 완료 모드**는 같은 보드가 다른 상태로
보이는 것뿐이다.

- 설계 모드: 책상을 눌러 삭제, 빈 칸을 눌러 추가, 드래그로 이동. 줄/분단
  단위로 통째로 추가·삭제도 가능. "통로"는 별도 옵션이 아니라 그냥 책상을
  안 놓은 빈 칸이다.
- 배치 시작을 누르면 책상이 전부 비워진 채로 잠긴다(더 이상 편집 불가).
  책상을 누르면 그 자리 학생 이름이 화면 전체에 크게 뜬다 — 몰래 배정한
  줄 지정을 학생 스스로도 클릭 전엔 알 수 없다.
- "다시 설계" 버튼으로 편집 모드로 되돌아갈 수 있다. 이번 배치는 다음번
  "직전과 다른 자리/짝" 판단의 기준(`prev`)으로 남는다.
- "전체화면"은 별도 화면이 아니라 같은 보드를 확대해서 보여줄 뿐이다 —
  네이티브 Fullscreen API가 막힌 환경(관리형 브라우저 등)에서도 하단
  버튼으로 항상 빠져나올 수 있게 액션바는 전체화면 중에도 숨기지 않는다.

## 명렬표 업로드

설정 패널에서 CSV 양식을 내려받아 채운 뒤 업로드한다. 두 칸짜리 양식이다:

```
이름,줄배정
김민준,
이서연,1
```

`줄배정`을 비우면 자동 배치, 숫자(1부터)를 쓰면 그 학생은 항상 그 줄에만
앉는다 — 학생 본인은 이 사실을 알 수 없다(클릭해야 자리를 확인하므로).
업로드는 기존 명단을 통째로 대체한다. CSV가 없어도 패널 안에서 이름을 하나씩
입력해 추가할 수 있고, 이때도 각 학생 옆 드롭다운으로 줄을 지정할 수 있다.

## 배정 엔진

단순 셔플이 아니다. 교실에서 실제로 필요한 건 "완전 랜덤"이 아니라
"이 학생은 항상 뒷줄, 저 둘은 떼어놓고, 지난번이랑 다르게"이기 때문에
제약 만족 문제로 푼다.

지원하는 규칙:

- **고정석** — 특정 학생을 특정 책상에 못박음
- **줄 지정** — 명렬표의 `줄배정` 칸. "정확히 이 줄"이라 완화 대상이 아니다 —
  명단에 명시된 값을 조용히 무시하면 안 되므로, 충돌하면 배치 자체가 실패하고
  이유를 알린다
- **짝 금지** — 두 학생이 짝꿍이 되지 않게. 통로(=빈 칸) 건너편은 짝으로 치지 않음
- **직전과 다른 자리** — 전원 이동
- **직전과 다른 짝** — 지난번 짝꿍 회피

MRV(선택지가 적은 학생부터) 휴리스틱 + 백트래킹으로 탐색한다.
짝 금지·직전 회피 규칙이 서로 충돌해서 답이 없으면 포기하지 않고 **완화
가능한 규칙을 정해진 순서로 하나씩 끄면서** 다시 시도하고, 무엇을 못
지켰는지 화면에 알린다. 다만 줄 지정과 고정석은 완화 대상이 아니다 — 교사가
명시한 값이니 조용히 무시하는 대신 즉시 실패로 알린다.

`seed`를 결과와 함께 저장하므로 같은 입력 + 같은 seed = 같은 결과다.
"다시 돌려봐" 요구에 재현이 되고, 공정성 시비도 막을 수 있다.

## 저장 · 공유

`store.js`가 Firestore(`seat_rooms` 컬렉션)에 저장한다. 로그인 화면 없이
`firebase-config.js`의 익명 인증으로 브라우저마다 uid를 받고, 그 uid를
좌석표의 `ownerUid`로 기록한다.

- 방은 URL의 `?room=<id>`로 식별한다. 처음 뭔가 바뀌면(디바운스 600ms)
  Firestore에 새 문서를 만들고 주소창에 자동으로 반영된다.
- **공유** 아이콘이 그 링크를 클립보드에 복사한다.
- 링크를 받은 사람은 같은 문서를 볼 수 있지만(rules: read는 열려 있음),
  자기 uid가 `ownerUid`와 다르면 쓰기가 막힌다 — 그래서 자동으로
  **읽기 전용 뷰**가 된다(제목 입력·설정 톱니바퀴·보드 편집 도구가 숨겨지고
  보드만 보임). 배치가 끝난 뒤라면 책상 클릭 공개·전체화면·인쇄는 뷰어도
  그대로 쓸 수 있다(로컬 연출일 뿐 저장을 건드리지 않으므로).
- Firestore를 못 붙였을 때(오프라인, 아직 익명 인증 안 켬 등)는 토스트로
  알리고 로컬 상태로 계속 쓸 수 있다 — 다만 저장은 안 된다.

## 현재 한계

인쇄는 브라우저 인쇄를 그대로 쓴다. PNG 내보내기는 아직 없다. CSV의 쉼표
이스케이프(따옴표로 감싼 필드)는 지원하지 않는다 — 한글 이름에 쉼표가 들어갈
일이 거의 없어서 단순 분할로 충분하다고 보고 생략했다.

## Firestore 규칙

`firestore.rules`가 이 앱의 실제 방어선이다. 로그인 화면이 없는 대신 익명
인증(Anonymous Auth)으로 브라우저마다 uid를 받아 좌석표 소유자로 기록한다 —
사용자는 로그인을 의식하지 않지만 규칙은 소유자를 구분할 수 있다.

- **읽기는 열려 있다** — 공유 링크를 아는 사람이 배치도를 볼 수 있어야 하므로.
  문서 ID(자동 생성 긴 문자열)가 사실상 비밀번호 역할을 한다.
- **쓰기는 만든 사람만.** `create`는 `ownerUid == request.auth.uid`를 강제하고,
  `update`는 기존 문서의 `ownerUid`와 일치해야 하며 그 값 자체는 바꿀 수 없다.
- 스키마도 검증한다 — 허용된 필드 외에는 거부, `desks`/`members`는 최대
  80개, `updatedAt`은 서버 시각과 일치해야 함(클라이언트가 시각을 위조 못 하게).
  책상 하나하나의 형태까지는 규칙에서 깊게 검증하지 않는다(리스트 길이만
  제한) — Firestore 규칙 문법상 리스트 원소 하나하나를 검사하는 비용이 크고,
  형태가 어긋난 데이터는 클라이언트가 렌더링에서 자연히 무시하기 때문이다.
- 정의하지 않은 컬렉션은 기본적으로 전부 거부된다.

**절대 테스트 모드(`allow read, write: if request.time < timestamp.date(...)`)를
쓰지 않는다.** 그 규칙은 지정한 날짜가 지나면 조건이 거짓이 되어 전 사이트가
갑자기 전부 거부로 뒤집힌다 — 30일 뒤 접근이 막히는 원인이 이것이다.

규칙은 `rules-test/`에서 실제 Firestore 에뮬레이터로 검증한다 (자세한 건
`rules-test/README.md`):

```sh
cd seatchange
npm --prefix rules-test install
npx firebase-tools emulators:exec --only firestore --project demo-seatchange \
  "node rules-test/firestore.rules.test.mjs"
```

Firebase 콘솔의 Firestore → Rules 탭에 `firestore.rules` 내용을 그대로
붙여넣으면 된다. **Authentication에서 "익명" 로그인 제공업체도 켜야 한다** —
안 켜면 `whenSignedIn()`이 끝나지 않아 저장이 전부 실패한다.

스키마를 바꿀 때(새 필드 추가 등) `firestore.rules`의 `validRoom()`과
`store.js`의 `FIELDS` 목록을 같이 고쳐야 한다 — 둘이 어긋나면 앱은 정상으로
보이다가 저장 시점에 조용히 `permission-denied`로 실패한다.
